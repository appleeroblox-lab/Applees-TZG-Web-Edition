# Social and world fixes v90

Media-only messages no longer append an empty text node/bubble or reserve its grid row. Message options share the sender header; images and voice players follow immediately below. Deleted posts use plain translucent notices, including own messages. Group/DM details open in a separate native modal with a scrolling body. The conversation is hidden and drafts are restored when returning. Group owner controls, photo selection and membership actions remain available.

The top Party badge shows the sum of unread messages (2 + 5 = 7). The Chats tab still counts unread conversations. Each conversation retains its own message count. New incoming messages/requests use the global-chat notification sound, without repeating on unchanged polls; initial history stays silent. A navigation text-hiding rule is explicitly overridden for the Party badge. Browser audio still requires a user gesture.

The GIF browser now uses https://nekos.best rather than Wikimedia Commons. It loads up to 60 random reaction GIFs per Explore batch, with category chips, GIF-only metadata search, Load more, duplicate filtering and a 180-tile gallery cap. Only visible/near-visible tiles load/animate; leaving the viewport removes their image source. Files are revalidated on download: exact approved provider URL, GIF MIME/signature, valid dimensions up to 1024×1024, at least two image frames, and the existing 1 MB upload limit. Oversized or invalid selections report an error. This is an anime/reaction GIF catalog; arbitrary search uses provider metadata, not a general web image search. No new API key or SQL setup is required. Provider docs: https://docs.nekos.best/getting-started/api-endpoints.html and https://docs.nekos.best/getting-started/api-reference.html .

Universe toggles open/closed when its button is pressed again. Grass is denser by default; Settings → Grass Amount persists 0–200% on this device. Mobile/compatibility modes cap candidates at 192 patches per chunk at 200%; grass remains in existing batched scenery meshes. Run is immediately left of Jump on the right side of the screen.

Each solid world has eight deterministic village sites. Villages use six larger houses with spaced roofs and internal doorstep paths. Launch-pad roads remain connected to the Earth shops, but no longer lead to villages. The original two village locations remain stable. Distant generated village blocks unload and regenerate from compact identities; open doors and mined/destroyed blocks persist. Player blocks survive unloading and do not prevent an already discovered village from reappearing. Saved block attachments may temporarily restore their supporting village during load for mount validation; normal streaming prunes distant sites. Rendering retains existing instanced block batches and per-range visibility. On coarse-pointer devices, village windows, doors and torches use a 130 m detail range; opaque house batches retain the terrain visibility range, and player-built torches keep their existing range.

Validation: media classification; plain deleted posts; 120 unique mock-provider results; rejection of static/non-GIF files; live provider metadata and a 289,756-byte animated GIF; eight sites/six houses; no pad-village road routes; unload/return/save restoration; player-block preservation; 0–200% grass bounds; unread sums, sound deduplication and draft restoration. Desktop and 844×390 browser checks exercise the real modal, badge visibility, media rows, 60→120 GIF loading/selection, Run/Jump positions and real terrain shader. Existing account/social/device/gameplay and world suites pass. The real WebGL fixture retains seven terrain/scenery draw calls with denser grass. Physical-device FPS was not measured.

No new database migration is needed. Existing account/inventory/social server policies and developer message logs are unchanged.
